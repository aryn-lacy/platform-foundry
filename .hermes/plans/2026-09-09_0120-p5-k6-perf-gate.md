# P5: k6 Performance Regression Gate — Implementation Plan

> **For Hermes:** Execute task-by-task on branch `feat/p5-perf`. Docs are the spec (issue #5, ADR-005, k6/README contract, architecture §5). Whole-file authoring. PR = draft → all-green CI → code-reviewer kanban card (defaults only) → Aryn merges.

**Goal:** Issue #5 — the perf-regression bonus made real and executable: `k6/smoke.js` VU-ramp profile, committed baselines, `perf.yml` diff-vs-baseline gate that fails red on regression, and the DoD: a synthetic +15% latency fixture must flip the gate red.

**Architecture:** Two moments, per ADR-005: k6 is the **pre-merge/pre-rollout gate in CI** (depends on nothing but the endpoint); the in-cluster AnalysisTemplate guard already shipped in P3. Baselines are versioned JSON in git; the gate = fixed load profile → summary metrics → tolerance diff vs baseline → non-zero exit on breach. Same cost-free posture as P4: no live endpoint exists, so CI runs the profile against a **local throwaway target** and the diff-vs-baseline logic is what's proven green/red — exactly like the policy-demo branch proved checkov.

**Tech stack:** k6 (grafana/k6, pinned), GitHub Actions (`grafana/k6-action` or direct binary), jq for the diff, bash. No new Terraform. No cluster creds.

## Design decisions needing Aryn's call

- **D1 — No live dev endpoint: what does k6 hit?** Overlays carry no Ingress/DNS (ALB endpoint is documented as out-of-band). Options:
  - (a) **CI boots the backend image locally and profiles it** (docker run + k6 against localhost) — real requests, real latencies, real regression semantics; slowest but most honest (RECOMMENDED).
  - (b) Mock HTTP target (nginx serving static) — proves the harness, not the app.
  - (c) Skip-run-when-no-endpoint (like ECR gating) — weakest: no green run to show.
- **D2 — Baseline seeding source.** With (a), seed from the CI run itself (`scripts/seed-baseline.sh` extracts summary-handle JSON → `k6/baselines/dev.json`), committed deliberately with a documented regeneration procedure (issue text: "how a baseline gets (re)generated deliberately").
- **D3 — Tolerance.** Fail when p95 > baseline × 1.15 (+15% — matches the issue's DoD fixture) OR error rate > 1% absolute. p99 reported, not gated (noisy at low VUs; documented).

## Tasks

### Task 1: k6 binary + Makefile wiring
- `eget grafana/k6 --tag=v1.x` → `~/.local/bin`; add `tools` line; `make tools` idempotent.
- Verify: `k6 version` exit 0.

### Task 2: `k6/smoke.js` — the load profile
- Fixed profile, env-parameterized: `BASE_URL` (default `http://localhost:8080`), `DURATION` (default `30s`), `VUS` (default ramp 2→10).
- Scenarios: `articles_list` (GET /api/articles?limit=10), `tags` (GET /api/tags); per-scenario `thresholds`: `http_req_duration p(95)<3000` sanity ceiling, `http_req_failed rate<0.01`.
- `handleSummary()` exports `summary-handle.json` (the machine-readable metric set the diff consumes).
- Verify: `k6 run k6/smoke.js` against a local container exits 0.

### Task 3: `k6/baselines/dev.json` + `scripts/seed-baseline.sh`
- Seed script: run the profile against a target, extract p95/p99/error-rate per scenario from `summary-handle.json`, write the baseline JSON with metadata (date, target, k6 version, commit).
- Commit the seeded baseline (values from the Task 2 local run; documented as seeded-locally).
- Verify: script is idempotent; JSON validates; README updated (drop "lands with Phase 5").

### Task 4: `scripts/check-regression.sh` — the tolerance diff
- Inputs: `summary-handle.json` + baseline path + tolerance (default 1.15).
- Compares per-scenario p95 (gate) + error rate (gate) + p99 (report-only); prints a table; exits 1 on any breach with the offending metric named.
- Verify: unit-style dry run — hand-crafted summary JSON with +15%/+14.% p95 values → red/green respectively.

### Task 5: `.github/workflows/perf.yml`
- Trigger: PR + push-to-main touching `apps/backend/**`, `k6/**`, `scripts/**`, workflow file (post-deploy semantics approximated as post-merge; documented honestly — no cluster exists).
- Job `smoke`: checkout → start the backend (docker run the CI-built image, or build from `apps/backend`; wait-on `/api/tags` 200) → `k6 run k6/smoke.js` (BASE_URL=localhost) → `check-regression.sh` vs `k6/baselines/dev.json`.
- Zero cloud creds; runs on the free runner.

### Task 6: The DoD proof — synthetic red fixture
- `k6/tests/regression-fixture.json` (+15% p95 hand-crafted summary) + a `make perf-test` target running `check-regression.sh` against it expecting **failure** — the same fixture discipline as the Rego rules.
- CI runs `make perf-test` in the perf job (proves the gate can go red on every PR, cheaply).

### Task 8: DoD battery + PR

## Risks / tradeoffs

- **D1-a runtime**: container boot + JVM warmup in CI (~60-90s) — acceptable; concurrency-grouped.
- **JVM warmup skew**: first-request latency inflates p95; mitigated by ramp stage + sanity ceiling at 3s, and baselines seeded the same way (apples-to-apples).
- **Login-scenario deferral**: seeded-users prerequisite documented; smoke scope stays public endpoints (issue text names login/articles — articles covered; deferral explicit in the PR).
- **Baseline staleness**: regeneration procedure is the seed script; tolerance documented in the baseline metadata.
